**来源类型只有五种**：用户口述 / 本地文件 / 录音笔记 / 链接 / 截图。写第六种（"常识""一般认为""我记得"）就是编，不许进表。

**录音笔记必须带时间点**（`[HH:MM:SS]`），只写笔记 id 不算——一篇三小时的稿子里，同一件事可能在五个地方被提到，时间点才能回查原话。

## B. 引语白名单（正文里所有引号内容必须在这里）

| # | 引语原文 | 谁说的 | 出处 | 可否直接引用 |
|---|---|---|---|---|
| B1 | <原话，一字不改> | <人名 / 职务> | <录音 `[01:05:48]` / 链接 / 文件行号> | ✅ 可 |
| B2 | <原话> | <他人转述> | <录音 `[02:41:28]`> | ⚠️ 只能写"有人转述"，不能写成"我说" |
| B3 | <作者自己的话，如"这篇只有你能写"> | 本文作者 | 自撰 | ✅ 可（短语，不必溯源） |

**硬规则**：

1. 引号里的内容，必须能在 A 或 B 里找到出处。找不到 → `voice_lint.py` 报错，稿子不许进 qa。
2. **转述的不能写成亲历**。别人说"每个字都是我念出来的"，就写"课上有人转述过一句话"，不许写成"我说"。这条比措辞重要——它决定这篇文章是不是假的。
3. 长度 ≥8 字的引语一律硬核；2–7 字的短引语（"不是 A，是 B"这类自造句式）只提醒，可加进 `config.quote_exempt` 豁免。

## C. 待补物料（问用户的清单，跟着选题一起发过去）

> 写完这一节就跟 `01_topics.md` 一起发给用户，**一次回完，不另开一轮**。
> 每条只问一样，别问"你能多说点吗"。

### C1 场景（第 14 讲：场景是内容的最小单元）

- [ ] 现场几个人？在哪（具体到房间/城市）？几点到几点？
- [ ] 你眼前看到的第一样东西是什么（屏幕上是什么、桌上有什么）？
- [ ] 当时屋里什么反应（有人出声吗、谁先说话）？
- [ ] 这件事你是在哪做的（工位/家里/会议室）？手上在干什么？

### C2 数字（自曝其短靠这个）

- [ ] 花了多久？（分钟级，不许写"一会儿"）
- [ ] 出了几个 / 几篇 / 第几次？
- [ ] 有没有一个难看的数（没发出去几篇、亏了多少、错了几个）？

### C3 引语（最有分量，也最容易编）

- [ ] 谁原话说了什么？（能给链接、截图、录音时间点最好）
- [ ] 这句话是你亲耳听的，还是别人转述的？
- [ ] 有没有一句话是你自己当时想的，但没说出口？

### C4 收尾

- [ ] 这件事最后落定了没有？没落定的话，现在卡在哪？

## 使用规则

| 谁 | 能做什么 |
|---|---|
| 主控 | 建表、补表、把 C 节发给用户、把用户回答填回 A/B |
| writer | **只读**。正文每一处具体事实和引语，必须能在 A 或 B 找到对应行 |
| qa | 逐条核。正文出现 A/B 里没有的具体事实 → `facts` 维度扣分；编造引语 → 直接 `veto: unsourced_claim` |
| voice_lint.py | 自动核引语。找不到出处的引语报错并指名是哪一句 |
