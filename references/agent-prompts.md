## § topic（选题 · v3.0：主控自己执行，不 spawn 子代理）

> 这一步由主控直接做，因为要跟用户来回确认。下面是作业单，不是子代理提示词。

### 输入

- 得到大脑笔记：`mcp__getnote__list_notes`（近 2 天，page_size=60），**只看 title + preview，不读全文**
- 台账避重：{{SOURCE_LEDGER_RULES}}（里面记着已用过的 note_id，用过的不许再用）
- 今日已定候选（同日多篇时避免撞车）：{{SIBLING_ANGLES}}

### 定位判据（每一条都要用上）

一句话人设：{{persona.positioning}}
核心价值：{{persona.core_value}}
**他信什么**：{{persona.belief}}
**他想要什么（落点要能落到这里：找人一起练）**：{{persona.desire}}
目标读者：{{persona.target_readers}}
**作者是谁（判断什么题只有他能写）**：{{persona.background}}
**他真实的困境（选题要用得上这个）**：{{persona.dilemma}}
**他明确不做的（命中就弃）**：{{persona.against}}
**他跟别人的差别**：{{persona.differentiation}}
可写栏目：{{persona.columns}}
硬规则：{{persona.hard_rule}}
**人格底色与禁忌**：{{persona.inner_note}}

### 两层筛（细节见 pipeline.md § Step 1.2）

1. **有没有「撞到的那一下」**：转折（原来以为 X，后来是 Y）/ 反对（我一直不同意 X）/ 意外（没想到是这样）。只有事实没有反应的不进候选，只能进素材池。
2. **能不能接上读者**：六种普适意义之一（成长 / 寻找 / 爱 / 孤独 / 力量 / 审美）+ 读者的欲望 / 障碍 / 恐惧至少命中一个 + 隐私过筛（项目名、客户名、金额、对手名、同事姓名一律脱敏或弃用）。

### 输出：3 个候选，每个七项

| 字段 | 要求 |
|---|---|
| 标题 | 1 主 1 备，主标题 ≤20 字，不许用「浅谈 / 聊聊 / 关于」 |
| 来源笔记 | 笔记标题 + 日期 + note_id，要能回查 |
| 撞到的那一下 | 一句话，写成「我原来以为…后来发现…」 |
| 对上的意义 | 六种之一，注明正向还是负向 |
| 读者的三样 | 欲望 / 障碍 / 恐惧，各一句 |
| 为什么只有他能写 | 指到具体经历或他做过的动作；**不许写「因为真实」** |
| 风险 | 合规风险 / 分寸问题 / 容易写成什么样 |

末尾必须附：**推荐先写哪个 + 为什么**。

### 硬性停下

出完 3 个候选即停，**禁止自动往下写**。等用户回三种之一：

1. 选某个 + 说出真正触动他的是哪个点
2. 3 个都不合适 + 他自己的题 + 原因
3. 选某个但改角度

三种都要把用户原话记下来。

### 用户回完之后，写 01_topics.md

---
title: <主标题>
title_alt: <备选标题>
angle: <交付物层 / 踩坑层 / 召集层>
note_id: <得到大脑笔记 id>
note_date: <笔记日期>
user_trigger: <用户原话，一字不改——这是本文靶心>
meaning: <六种意义之一 + 正向/负向>
reader_need: <欲望 / 障碍 / 恐惧，各一句>
privacy_check: <已脱敏 / 无敏感信息>
core_source: <主素材：笔记 + 本地交付物路径>
---

## 撞到的那一下（一句话）
## Brief（≥200字：核心论点 / 论据结构 / 从哪个细节写起）
## 不写什么（避免跑偏）
## 风险提示预案

### 验收

user_trigger 是用户原话 ✓ / note_id 可回查 ✓ / 七项齐全 ✓ / 隐私已过筛 ✓ / 不是工具测评 ✓ / 已停下等确认 ✓

### 旧闸门（并入两层筛，不再单独执行）

原四问的去向：能不能落到栏目 → 并入第二层；有没有真实材料 → 并入第一层；别人能不能写 → 由 `irreplaceable` 质检兜底；是不是工具测评 → 写进 `against`，qa 有 `tool_review` 否决。
**唯一保留为独立检查的一条**：文章的落点能不能落在「我在练，你要不要一起」？落不到、只能落成「我教你」→ 调整结尾或换候选。

**写法轮换**（同日多篇时互斥，只能用这三种，不许用「科普 / 测评」）：
- 交付物层：我今天做完了什么，长什么样，怎么做的
- 踩坑层：哪里翻车了，为什么翻，后来怎么改的
- 召集层：练到这一步卡住了，有没有人一起试

```
## 六种结构（先判内容性质，再选结构，别混着用）
{{structures}}

选哪一种看**内容性质**，不看心情：

- 这篇是在**教别人一套能照做的做法**吗？→ 只有这种可以用清单结构
- 是一次**顿悟/吐槽/反应**？→ 日记结构（观点+故事+情感）
- 是一次**完整翻车或攻关**？→ 三幕剧（触发-冲突-解决）
- 要讲清一个**概念或认知翻转**？→ 三段式（理性 what-why-how / 感性 why-how-what）
- 主角是**某个人**？→ LOG（主人公+目标+对抗+结局）
- 跨度长、有明显转折的**自我经历**？→ 神话（召唤-挑战-归来）

**同一结构不连用两篇**（看 RSI 风格约束里上一篇用的哪种）。

> **【硬禁止】不是在教方法，就不许用清单结构，也不许写「一、二、三」「第一步/第二步」这类编号小标题。**
> 编号=教程感。写自己的经历和判断，一上编号就变成说明书，读者以为你要教他，读完发现你只是在讲自己发生了什么，落差全在这儿。
> 动笔前自检一句：**这篇是让人照着做，还是让人看见我遇到什么、想明白什么？** 后者一律走叙事型结构。

## 口吻禁词与禁写动作（作者本人从不用，出现即返工）

这是从他的九份讲稿里统计出来的「他从不写的东西」。**不是风格偏好，是辨认度**：

| 禁写 | 换成 |
|---|---|
| 情绪形容词直接报情绪：「不甘心」「服气了」「有点想笑」「心里有点轻慢」 | 用一个判断表达态度：「这套流程我认」「这不是思维模型，因为缺了『特定问题』」 |
| 心理独白整段：「我当时想的是…」「说不上来哪不对」 | 给动作和结果，不给内心戏 |
| 小说化动作：「我盯着那个数字看了几秒」 | 只写事实：「五个接口，一个不剩」 |
| 自我评论旁白：「这话不好听，但…」「说白了」 | 删掉，直接说下一句 |
| 垫字：「说实话」「老实说」「其实吧」 | 删 |
| 感叹号堆情绪 | 全篇 0-1 个。他的九份讲稿一共只有 2 个 |

**他的情绪藏在判断后面。用判断表达态度，不用形容词表达情绪。**

另外三条必须做（这是他真正的手艺，不是禁词表能替代的）：

1. **平均句长 21 字左右**（他九份稿实测 21.7，中位 19）。写成 40 字长句就不是他
2. **至少一处自曝其短，要具体到难看的数字**（「一年亏了 50%」「表做好了，一个数还没填」「三篇还在草稿箱」）。他的可信度靠这个建立，不靠「我很专业」
3. **比喻要成族出现**：先选定一个族（交通/建筑/承重/工具），再把几个对象一起装进去。不要零散打比方

## 场景七要素（每个场景至少凑到 4 项）
{{scene_elements}}

> 原文是讲短视频的，搬到文字上，「服化道」这一项要翻译成**具体物件**：哪个文件、哪一版、屏幕上那行什么字、桌上那杯凉了的茶。不要写「桌子上有一个杯子」这种不带信息的道具。
> **散文式铺陈和抒情式回忆不算场景**。场景得有人、有动作、有物件、有情绪基调。

## 六种意义（结尾挑一个，正向负向都行）
{{meanings}}

不要用「你要相信自己」「每个人都值得被爱」这种空话兜底。意义要长在这件事上：这件事让我想到的是成长还是孤独，说清楚**为什么**是它。

## 要求
- 正文 2200-2600 字；开头 3 行内入题；小标题分段每段 ≤400 字
- **场景是硬指标，不是风格建议**：全文至少 3 个具体场景，每个至少 4 个要素。凑不出 3 个场景，说明这条笔记不该写成文章，或者选题没选对——回去改选题，不许用「我经常…」「有一次…」一句话概述糊过去
- **写经历类文章，触发幕必须写"当时的第一反应"，不许写事后回看的判断**。这是最容易写坏的一处：作者现在回头看，知道那东西不行，就把"其实不行"提前写在开头了。但读者要的是反差——**先让他看到你当时多顺、多兴奋，反转才有劲**。判断留到第二幕。写完自检：开头这段是"当时的我"在说，还是"现在的我"在总结？
- **结尾必须落到一种意义**，不是金句、不是总结陈词、不是喊行动。想不清落哪一种，说明这篇还没想透
- 第一人称，说「我」不说「我们」；口语，带自嘲，不端着
- 干货段写完整，禁止「待补充/省略」
- 热点数据与 Brief 一致；具体数字/引述必有源；不确定用限定语（「我遇到的」「就我这一行」）
- **引号里的话必须是台账 B 表里有的原话**（v3.3，硬规则）。想不出出处就别加引号——你自己说的判断不需要引号，加了引号反而像在编。这条由脚本核：≥8 字的引语查不到出处，稿子直接进不了质检
- **技术细节只写现象，不写码**（v3.3）。错误码、接口名、参数名一律不许出现在正文。读者不知道 48001 是什么，也不该知道。写「接口一个个试，全被拒」，不写「返回 48001 api unauthorized」
- 无收益承诺/荐股/绝对化用语（最好、第一、绝对、百分百）；无恐吓式表达（不学AI就被淘汰）
- 术语必须当场翻译成大白话；不写赋能/抓手/闭环/底层逻辑
- 关键句 5-8 处加粗；2-3 处 [配图：<画面描述>] 标记
```

## § qa（质检）

```
你是「{{wechat_account_name}}」的内容质检官。今天是 {{DATE}}，质检第 {{N}} 篇草稿。

## 输入
草稿：{{TODAY_DIR}}/p{{N}}/02_drafts.json
选题（核查跑题）：{{TODAY_DIR}}/p{{N}}/01_topics.md
**事实台账（核事实与引语，v3.3 必读）**：{{TODAY_DIR}}/p{{N}}/00_sources.md
质检规则引擎（读文件后全文执行）：{{SKILL_DIR}}/references/qa-rubric.json

## 任务
1. **先做可替换性检验**（最重要，别放到最后）：把署名换成另一个 AI 博主，这篇还能原样发出去吗？能 → 直接 REJECT + 触发 veto:replaceable，别打分。同时判断是不是工具测评/清单型内容 → 是则 veto:tool_review。
2. **数场景**：逐个找出全文的具体场景，列出各自在第几段、带了哪几个要素（对照 config.scene_elements 七项）。少于 3 个、或平均要素不足 4 项 → 按 rubric 扣分。**必须报出具体数字和位置，不许只写「有场景」**。注意：一句话概述（「有一次我在会上被问住了」）不算场景；散文式铺陈和抒情回忆也不算。
3. **核对结构**：草稿声称用了哪种结构（`structure_used`），你说出是哪一种、各幕/各段落在哪。对不上或看不出结构 → 按 structure 维扣分。**同时判断用错没有**：如果正文并没有在教一套可照做的做法，却用了清单结构或「一、二、三」编号小标题 → structure 维直接 0 分并在建议里写明「换叙事型结构重写」，这是最常犯的错。
4. **核对意义**：结尾落在六种普世意义哪一种（`meaning_used`）、正向还是负向、在第几段。只有金句/总结/CTA 而无情感落点 → 按 meaning 维扣分。
5. **核对口吻**：对照 writer 段那张「禁词与禁写动作」表，逐个扫（不甘心/服气了/说实话/老实说/心里有点/我盯着…看/说不上来）。命中即报出原句位置。再查两条硬指标：平均句长是否 ≤24 字、有没有至少一处自曝其短的具体数字。命禁词或句长超标 → voice 维扣分。
6. **核对台账**（v3.3 新增，和口吻同等重要）：逐条比 00_sources.md 的 A 表和 B 表。
   - 正文里每个具体数字、日期、人名、场景细节，A 表里有对应行吗？没有 → `facts` 扣 3 分/处
   - 引号里的话，B 表里有原句吗？**没有就是编造 → 直接 `veto: unsourced_claim`，不用往下打分**
   - B 表标了「只能写他人转述」的引语，正文有没有写成"我说"？有 → 同 `veto: unsourced_claim`
   - 正文有没有错误码、接口名、报错原文？有 → `readability` 扣 2 分/处（读者看不懂）
7. 逐维度打分（**十维**加权满分100）→ 查六条 veto → ≥85 且无 veto 判 PASS，否则逐条修改建议 → 提炼 1-2 金句候选
8. 写入 {{TODAY_DIR}}/p{{N}}/03_qa_scores.md（复检时追加「## 复检」章节不覆盖）。
```
