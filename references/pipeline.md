# 流水线详细编排（rsi-wechat-publisher v3.0，主控必读）

> 主控（WorkBuddy 会话）的动作手册。所有个人参数从 `config.json` 读取，禁止硬编码。

## 核心纪律（先读）

1. **执行前先读 config.json**：作者名/知识库 ID/每日篇数/persona 全部从配置取，拼进子代理提示词。
2. **产物目录**：`<项目根>/pipeline/<YYYY-MM-DD>/p1|p2|p3/`（项目根 = 当前工作区）。
3. **磁盘为准**：子代理返回后必须 Read 验证产物文件存在；缺 → 携失败原因补 spawn 一次。
4. **断点续跑**：启动先看近 2 天 `_status.json`，`finished!=true` 则缺哪步补哪步，禁止覆盖已验证产物。
5. **Truth-first**：素材不足允许减产（3→2→1→0），台账留痕，绝不凑数。
6. **选题处必须停**（v3.0 新增，最高优先级）：Step 1 出完 3 个候选就停，等用户回「选哪个 + 触动点」才能往下。**禁止自动 spawn writer**。这是全流程唯一的人工闸门，跳过去就等于退回「AI 生成」。
7. **没有台账不许动笔**（v3.3 新增，与第 6 条同级）：`00_sources.md` 不存在、或 C 节待补物料没回收，**不许 spawn writer**。缺料时写出来的东西，一定会自己填。填出来的就是编造。
8. **绝不群发**：post_draft.py 只进草稿箱；本地降级包也只是让人工手动发。
9. 凭证只在 `~/.config/`，绝不写进提示词、台账或 git 提交内容。
10. **要课程方法先查索引**（v3.5 新增）：需要于困困某一讲的具体方法时，**先读 `references/course-index.md` 拿文件路径，直接读那一个文件**；涉及第 26 讲的审稿，直接读 `references/yukunkun-7d-checklist.md`（已提炼，不用回原文）。**禁止在工作区全盘 grep 找课程内容**——13 万字逐字稿加 36 个笔记文件，搜一次要排十几个无关命中，这是纯浪费。

## 编排总览

```
主控
 ├── Step 0  预热：date 实测 → 断点盘点 → 建目录 → 读 config.json + _rsi_ledger.md 提炼硬约束
 ├── Step 0.5 热点采集（默认关闭，hotspot_enabled=false）：WebSearch → 热点候选池
 ├── Step 0.6 对标拆解（默认关闭，benchmark_enabled=false）：搜同赛道爆款 → 只拆骨架 → _benchmark.md
 ├── Step 0.7 素材查证（IMA 降为查证层）：只在该题需要政策/数据/行业背景时才查
 ├── Step 1  选题：主控从得到大脑当天笔记筛出 3 个候选 → **停，等用户选** → 01_topics.md
 ├── Step 1.5 **物料清单 + 事实台账**：把「我要你补什么」跟选题一起发给用户，回收后建 00_sources.md
 ├── Step 2  spawn writer ×N（并行）→ 各篇 02_drafts.json（**只许从台账取料**）
 ├── Step 2.5 **体检门禁**：voice_lint（禁词 + 引语溯源 + 技术黑话），exit 1 不许进 qa
 ├── Step 3  spawn qa ×N → 03_qa_scores.md（<85 打回 writer，同篇 ≤2 次，**超 2 次强制停下问用户**）
 ├── Step 4  spawn format ×N → 封面/插图 + article.html + CTA + post_draft.py 推草稿箱 → 04_publish_queue.md + format/manifest.json
 ├── Step 5  archive：bash scripts/archive_article.sh <日期> <产物目录>
 ├── Step 6  sync-ima：python3 scripts/sync_to_ima_wb.py <articles目录> <日期>
 └── Step 7  复盘：回写台账 + check_drift + _status.json finished:true + 日报简报
      └── 7a 数据回流（群发后第 3 天，手工抄表）：bash scripts/fetch_stats.sh
```

子代理提示词模板：`references/agent-prompts.md`（填充后 spawn，subagent_type=general-purpose）。

## Step 0 预热

1. `date '+%Y-%m-%d %H:%M %Z'` 实测日期。
2. 断点盘点近 2 天。
3. `mkdir -p pipeline/<日期>/p{1..N}`。
4. 读 config.json：拿到 kb_id、author、persona、articles_per_day。
5. 读 `_rsi_ledger.md` 提炼：素材避重（7 天内/累计≥2 次）、风格偏好结论、金句库、硬约束修正。
6. IMA/公众号凭证探测：`python3 scripts/diagnose.py --check` 可选；缺 IMA → Step 0.7/6 跳过；缺公众号 → format 降级本地包（简报标注）。

## Step 0.5 热点采集（默认关闭，`hotspot_enabled=false`）

跑 config.hotspot_queries 的 2-3 条查询 → 挑 5-10 条形成候选池（标题+一句摘要）。热点仅作钩子，主体观点必须来自自有素材。失败不阻断（纯库存选题）。

**v2.0 约束（定位改版后新增）**：
- 热点必须能接上"一份标书 / 一门课 / 一套投资记录"其中之一，接不上就不进候选池。
- **工具发布、工具更新、工具榜单类资讯一律排除**——本号明确不做工具测评。
- 热点只是开头那两三句的由头，不许成为文章主体。若某个热点想不出怎么接自己的经历，直接丢掉。

## Step 0.6 对标拆解（默认关闭，`config.benchmark_enabled=false`；手动置 true 才跑）

**目的**：给选题一个「结构参考」——看同赛道最近什么写法被市场验证过，别闭门造车。

1. **搜索**：跑 `config.benchmark_queries` 的搜索词；`config.benchmark_accounts` 非空时优先按号找。从中挑 `benchmark_top_n` 篇（默认 3）**同赛道、近期、明显爆过**的：阅读量/点赞/转发显著高于同类，或搜索排序靠前。
2. **拆解**：spawn benchmark 子代理（提示词见 `agent-prompts.md § benchmark`）→ 产出 `pipeline/<日期>/_benchmark.md`。
3. **传递**：Step 1 的 topic 提示词注入 `{{BENCHMARK_SKELETONS}}`（骨架结论），**只作结构参考**。

**四条红线**：

- **只拆骨架**（钩子类型 / 段落结构 / 节奏 / 受众 / 爆点），**禁止摘录原句、禁止复制段落**——对标文章的原句一个字都不许进任何产物文件。
- 骨架只影响「怎么排列」，不影响「说什么」：正文观点与论据仍必须全部来自自有素材（本地经历层 + IMA 行业/方法层）。
- **（v2.0 新增）禁拆工具测评/工具清单/大厂效率技巧类爆款**——config.benchmark_banned 里列的类型一律不拆。拆这类爆款等于把内容拉回同质化赛道。
- 搜不到合适爆款不阻断，写「本轮无对标」留痕，按原流程走。

## Step 0.7 素材查证（v3.0：IMA 降为查证层）

**核心变化**：选题不再从素材库里找。选题在 Step 1 从得到大脑当天笔记里出；这一步只在**题已经定了之后**补论据和背景。

| 层 | 来源 | 用途 |
|---|---|---|
| **经历层（写稿主料）** | `config.local_sources`：标书审核实战 / 标书审核失败调查 / 标书审查复盘 / 投标知识库 / 15-交流培训 | 案例细节、踩坑、可交付物 |
| **查证层** | IMA `新能源`（878 条：政策 / 项目管理 / 电力交易） | 只在文章需要政策、数据、行业背景时查，**必须标出处** |
| **方法查证** | IMA `AI`（156 条） | 只在需要核实某个工具用法时查，不作内容主体 |

动作：

1. 按已定选题判断需不需要外部论据：需要才查，不需要就跳过（个人经历型文章多数不需要）。
2. IMA 侧：ima-mcp 可用则 `get_knowledge_list` 逐层浏览 `ima_source_folders` 指定 folder；否则用凭证走 curl；都没有则不查。
3. `local_sources_pending` 里 path 为空的栏目**不出稿**，在日报写明「该栏目素材源待补」。

**硬约束**：
- 文章的核心事实（发生了什么、我怎么反应、我改了什么）只能来自得到大脑笔记或本地交付物，**不许来自 IMA**。IMA 只能补背景。
- 引用查证层内容必须标出处；查不到就写「我没查到确切数字」，不编。
- 涉及具体项目/客户/同事的，写进文章前必须脱敏（见《00-定位卡.md》合规边界）。

## Step 1 选题（v3.0 重写：得到大脑 → 3 个候选 → 人工选定）

**这一步是整条流水线的分水岭。** v2.0 及以前是「AI 出的题直接往下写」，写出来能替换；v3.0 起是「AI 从你的真实笔记里挑，你决定写哪个、为什么写」，写出来才是你的。

### 1.1 拉当天笔记（主控自己做，不 spawn 子代理）

```
mcp__getnote__list_notes(created_from=<今天-2天 00:00>, created_to=<明天 00:00>, page_size=60)
```

- 只看 `title` + `preview` 做第一遍粗分，**不读全文**——一天 40 条，全文读不起。
- **禁止按标题关键词排除。** 标题是 AI 自动概括的智能总结标题，会把三小时长谈压成「闲聊」、把一次顿悟压成「日常记录」。按标题排，丢掉的正是最真的东西。
- 标题含「闲聊 / 日常 / 闲谈 / 随想 / 杂谈 / 对话」的：**优先级调高，不是调低**。这类长对话里最容易出金句和真实状态。必须读内容再判断，不许跳过。
- 唯一降权的是 `note_type = img_text`（纯图像识别：饮食记录、物品照片）——降为素材（写稿时当细节），不进候选。但若同一天其他笔记提到同一件事并带判断，那条照常进候选。
- 优先级最高的是 `recorder_flash_audio`（随手记）、`internal_record`、`plain_text`——当下真实反应，最接近「撞到的那一下」。
- 排除台账里已用过的 `note_id`（笔记避重，见 `_rsi_ledger.md`）。

**第二步：按信号强弱排序，只取前 8–10 条读全文**

打分只看摘要里出现的 `reaction_markers`（不读正文，只扫 preview）：

| 信号 | 加减分 |
|---|---|
| 转折类：原来 / 没想到 / 其实 / 反过来 | +3 |
| 判断类：我觉得 / 我认为 / 我发现 / 我的判断 | +2 |
| 行动类：我改了 / 我决定 / 不同意 / 这不对 | +3 |
| `recorder_flash_audio`（随手记） | +2 |
| `img_text` | −5（低于 0 直接不进候选） |

前 8–10 条才读全文（`get_note` / `get_note_transcript`）。**不读全量**——读不起，也没必要。

**第三步：两个抽样名额（不许省）**

每轮额外留 **2 个名额**，专门给「时长 > 1 小时 + 多人参与」的笔记，**不看分数**，直接读全文。

理由：这类长对话信息密度最高，但 AI 概括会把它们压成「闲聊」「日常对话」四个字，分数自然低，按分数排永远轮不到读。

> **两条铁律**：
> 1. 排除依据是「有没有反应」，不是「标题像不像正经事」。
> 2. **任何引用笔记的地方，必须同时写 note_id 和创建时间，缺一个就不许写。**（2026-11-02 教训：把 5 月的笔记当成 11 月的，因为只看了标题没核时间）

### 1.2 两层筛（判据全部来自课程，不许自创标准）

**第一层：有没有「撞到的那一下」**

> 判断依据**只来自正文，不来自标题**。标题只用来决定「哪几条值得读」。

不是「发生了这件事」，是「我原来的想法被打了一下」。三种形态任一即算：

- 转折：我原来以为 X，后来发现是 Y
- 反对：我一直不同意 X
- 意外：没想到 X 居然是这样

靠 `reaction_markers`（我觉得 / 我发现 / 其实 / 反过来 / 突然想到 / 不同意 / 我改了…）识别。**只有事实没有反应的，不进候选**（可进素材池）。

**第二层：能不能接上读者**

- 对得上六种普适意义之一：成长 / 寻找 / 爱 / 孤独 / 力量 / 审美（19 讲），注明正向还是负向展开
- 读者的欲望 / 障碍 / 恐惧 至少命中一个（06 讲）
- 隐私过筛：命中 `privacy_blocklist` 的（项目名 / 客户名 / 金额 / 对手名 / 同事姓名 / 未公开条款），**要么脱敏成「某次项目评审」，要么整条不用**

两层都过 → 候选。只过第一层 → 存素材池，不推荐。都不过 → 弃。

**对候选才读全文**（`mcp__getnote__get_note` 或 `get_note_transcript`），提取原话、时间、细节。

### 1.3 出 3 个候选（固定格式，缺一不可）

| 字段 | 要求 |
|---|---|
| 标题 | 1 主 1 备，主标题 ≤20 字，不许用「浅谈 / 聊聊 / 关于」 |
| 来源笔记 | 笔记标题 + 日期 + note_id，要能回查 |
| 撞到的那一下 | 一句话，写成「我原来以为…后来发现…」 |
| 对上的意义 | 成长 / 寻找 / 爱 / 孤独 / 力量 / 审美，注明正向还是负向 |
| 读者的三样 | 欲望 / 障碍 / 恐惧，各一句 |
| 为什么只有他能写 | 指到具体经历或他做过的动作；**不许写「因为真实」** |
| 风险 | 合规风险 / 分寸问题 / 容易写成什么样 |

末尾附一句：**推荐先写哪个 + 为什么**。

### 1.4 停，等用户回（硬性，不许跳过）

**出完 3 个候选必须停，禁止自动 spawn writer。**

| 用户回什么 | 主控做什么 |
|---|---|
| 选某个 + 说触动点 | 把他**原话**写进 `01_topics.md` 的 `user_trigger`，一字不改 |
| 3 个都不合适 + 给题 + 原因 | 用他的题，原因进 `user_trigger`；再补一道检查——这题有没有真实笔记或交付物支撑？没有就回去问他 |
| 选某个但改角度 | `user_trigger` = 他改的理由原话；`title` 按他说的调 |

`user_trigger` 是这篇的靶心：**writer 必须围绕它写，qa 必须检查有没有打到它**。

### 1.5 写 01_topics.md

必含字段：`title` / `angle` / `note_id` / `note_date` / `user_trigger` / `meaning` / `reader_need` / `privacy_check` / `core_source`。模板见 `agent-prompts.md § topic`。

## Step 1.6 物料清单与事实台账（v3.3 新增，本流程最重要的一处补丁）

### 为什么加这一步

2026-11-02 那篇稿子，旧流程走下来是这样：

```
选题 → writer 直接写 → qa 打 71 分 → 才回头问用户要料 → 用户补 → 91 分
```

**顺序反了。** writer 手上没有"现场几个人、屏幕上先出什么、那三篇发没发"，但稿子已经在写了。缺料时没人问，就会自己填——填出来一句编造引语（「我不甘心的就是这个」），全程绿灯，用户第八次读稿才发现。

一句话：**旧流程把"采访"放在了"交稿"之后。**

### 动作

**① 写 `00_sources.md`，跟 `01_topics.md` 一起发给用户**

模板：`templates/00_sources.md`。向用户发的不是"你能多说点吗"，是三组具体问句：

- **场景**：几个人？在哪？屏幕上先出的是什么？当时屋里什么反应？
- **数字**：花了多久（分钟级）？几篇？有没有一个难看的数？
- **引语**：谁原话说了什么？是你亲耳听的还是别人转述的？

**必须跟选题一起发，不许另开一轮。** 用户一次回完两件事。一天三篇，多一轮问答就跑不动——这条是这一步能不能活下来的关键。

**② 用户回完，主控把答案填进 A 表（事实）和 B 表（引语），状态改成"可开写"**

**③ writer 只读这份台账。** 正文每一处具体事实和引语，必须能在 A 或 B 找到对应行。找不到就写限定语（"我遇到的""就我这一行"），不许自己造。

**④ qa 拿台账逐条核**，见 `qa-rubric.json` 的 `facts` 维度。

**⑤ `voice_lint.py` 自动核引语**：长度 ≥8 字的引号内容，必须在台账里查得到，查不到直接 exit 1。

### 三条硬规则

1. **来源类型只有五种**：用户口述 / 本地文件 / 录音笔记 / 链接 / 截图。写第六种（"常识""一般认为""我记得"）就是编。
2. **录音笔记必须带时间点**（`[HH:MM:SS]`）。只写 note_id 不算——三小时的稿子里同一件事可能提五次，时间点才能回查。
3. **转述不能写成亲历。** 别人说"每个字都是我念出来的"，就只能写"课上有人转述过一句话"，不许写成"我说"。这条比措辞重要，它决定这篇是不是假的。

### 用户直接给题的时候怎么办

题由用户给，Step 1 的"筛 3 个候选"可以跳过，但**不能整步跳过**——要把它变成"把你给的题翻译成 Brief（`01_topics.md`）+ 物料清单（`00_sources.md` C 节）"。跳过的代价是 `user_trigger` 和 `meaning` 没人定，writer 只能自己猜，写出来必偏。

## Step 2-3（子代理执行，提示词见 agent-prompts.md）

- **定位检查已前移到 Step 1**：两层筛已经卡过「有没有真实反应」「接不接得上读者」「隐私」。Step 2 不再重筛题目，只做两件事：围绕 `user_trigger` 写，不许写成工具测评。
- **writer 必做（v3.3 五条硬约束）**：
  1. 先判内容性质，再选结构（`config.structures` **六种**：清单/日记/三幕剧/三段式/LOG/神话），同一结构不连用两篇 → 写进 `structure_used` + `structure_why`
  2. **不是在教别人一套能照做的做法，就禁用清单结构和「一、二、三」「第一步」编号小标题**（见 `config._structure_hard_rule`）。编号=教程感，写自己的经历一上编号就变说明书
  3. 场景 ≥3 个、每个 ≥4 要素（`config.scene_elements` 七项）→ 写进 `scene_count`
  4. 结尾落到六种意义之一（`config.meanings`），不许用金句/CTA 顶替 → 写进 `meaning_used`
  5. **只许从 `00_sources.md` 取料**（v3.3 新增）。正文每一处具体事实和引语，必须能在 A 表或 B 表找到对应行。找不到就写限定语（"我遇到的""就我这一行"）或删掉，**不许自己造**。writer 对台账只有读权限
- **写完必跑体检（硬门禁，不许跳过）**：
  ```bash
  python scripts/voice_lint.py --dir <稿件目录>
  ```
  v3.3 起查三类，**exit 1 就不许进 qa**：
  1. **口吻**——`config.voice_blacklist` 六类禁词（情绪形容词/自我评价/心理独白/小说化动作/垫字/讲稿专用），外加句长、感叹号、我你比、编号小标题
  2. **引语溯源**——正文引号里 ≥8 字的内容，必须在 `00_sources.md` 的 B 表查得到。查不到直接 FAIL，指名哪一句。**这条治的是"编一句像别人说的话"**：2026-11-02 那次编的就是「我不甘心的就是这个」，禁词表永远扫不出来
  3. **技术黑话**——5 位错误码 / `api unauthorized` / `cgi-bin/...` / HTTP 状态码 一律不许进正文。用户原话：**「48001 是什么东西，阅读这能看懂吗？」** 要写就写现象：接口被拒、没权限、卡在账号类型上
  为什么这道门必须存在：同一个词删了又写回来两次、同一句引语编了两次，肉眼和自觉都拦不住，只能让机器每次拦一遍
- **改稿次数上锁（v3.3）**：`_status.json` 记 `revision_count`，**到 2 次强制停下问用户**——换题，还是接受现状。不许主控自己接着改第三、第四、第五版。2026-11-02 那篇改了 5 版，规矩写在文档里却没人数，等于没有
- **writer 必做**：读 `01_topics.md` 的 `user_trigger`，整篇围绕它——开头 3 行内点到，结尾回到它，中途不换论点。
- **qa 审稿主流程 = 于困困第 26 讲七维度**（v3.5 新增）：按「主旨 → 结构 → 场景 → 开头 → 结尾 → 对话 → 气质」逐维过，每维必须给「判定 / 位置 / 为什么不达标 / 怎么改」四样，判定只用**合格 · 半合格 · 不合格**三档。细则读 `references/yukunkun-7d-checklist.md`，**不许凭印象、也不必回原文**。
- **两套质检的关系（别混）**：七维度是**诊断顺序**（先找问题在哪），十维加权是**量化口径**（再算多少分）。用法是先按七维度把毛病挖出来，再用 `qa-rubric.json` 打分。只打分不诊断，会得出"86 分但不知道为什么不好看"这种结果。
- qa 规则：`references/qa-rubric.json`（**十维**加权 + 六条一票否决：compliance / content_hollow / source_dup / unsourced_claim / **replaceable / tool_review**）。
- **可替换性优先**：qa 第一步就是"把署名换掉还能不能发"，能发直接 REJECT，不用往下打分。
- **场景必须数出来**：qa 要逐个列出「第几段 → 哪几个要素」，报数字不报结论。一句话概述不算场景。
- **打到靶心没有**：qa 必查——`user_trigger` 那个点有没有被写透？只提一句就带过 = 不合格，退回 writer。
- 打回流程：qa REVISE → 携修改建议补 spawn writer（改 02_drafts.json 原地覆盖）→ qa 复检（追加到 03_qa_scores.md）；同篇 ≤2 次，仍不过就换候选（回到 Step 1 的 3 个候选里换一个，单篇处理）。
- **分清可修和必死**：场景不足、意义缺失是**可修**（退回 writer 补，别换题）；命中 replaceable（连一个具体场景都凑不出）是**必死**（换选题，改文字救不回来）。别把可修的判死，也别让必死的反复改。

### 7a 数据回流（发出去之后才做的环节）

发布不等于结束。群发后第 3 天做一次回流，这是整条流水线里**唯一往回看**的一环。

**先记住这个硬事实**：本号是未认证个人订阅号，微信 `datacube/*` 接口一律返回 `48001 api unauthorized`——阅读数、粉丝数、已发布列表**一个都拉不到**。所以回流走手工表，不靠脚本自动同步。脚本里保留了 `--api` 分支，将来账号认证了可以直接切，但现在跑了也只会拿到一条明确的报错。

三步：

```bash
# 1) 群发完当天，标记这篇已发（不标，脚本认为它还在草稿箱，直接跳过）
bash scripts/fetch_stats.sh --mark-published 2026-11-01

# 2) 生成待填表 → data/stats_input.md
bash scripts/fetch_stats.sh --init

# 3) 后台 → 内容分析 → 单篇群发，抄「送达 / 阅读人数 / 分享」三列到表里，然后汇总
bash scripts/fetch_stats.sh
```

脚本会算派生指标、写进 `articles/<日期>/meta.json` 的 `stats`（含 `stats_history`，同一篇多次采集留最近 8 次），并重写台账第 7 节。

**看什么，什么阶段看**：

| 指标 | 怎么算 | 现在该不该盯 |
|------|--------|-------------|
| 打开率 | 阅读人数 ÷ 送达 | **先别盯**。粉丝没到千，分母太小，多一个人点开比例就翻倍，全是噪声 |
| 分享率 | 分享次数 ÷ 阅读人数 | **现在就盯这个**。粉丝少的时候，它才是唯一的真信号 |
| 收藏率 | 收藏 ÷ 阅读人数 | 和分享率配对看：分享=想让人看到，收藏=想自己留着再用 |
| 阅读来源占比 | 后台手抄五段百分比 | 一个月挑**一篇**看，不要每篇都看 |

**分入口诊断（手工，可选）**：先看「公众号会话」占比——低，说明封面/标题没勾住老读者；再看「朋友圈 + 聊天」——低，说明导语没让人想转。这个顺序本身是对的，但它要等样本量够分才有意义，现在做只会对着噪声改封面。**这一步没有接口，也不值得为它做自动化。**

> ⚠️ 数据里的一个坑：v1 脚本把 `ori_page_read_count`（原文页阅读次数）当点赞写进台账。老台账里如果有「点赞」列的数字，那是阅读量，不是点赞，别拿来当结论。v2 起已修正，旧行存到台账 7b 仅供溯源。
